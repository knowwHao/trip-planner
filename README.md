# 旅遊規劃

和旅伴一起排行程、記旅費的網頁：景點、時間、Google 地圖連結大家一起編輯，有人改了其他人畫面會自動更新；旅費可以記當地幣別或新台幣，結算一律換成新台幣，算出最少筆數的轉帳建議。

- 前端：Vue 3 + Vite + TypeScript + Tailwind CSS v4，可安裝成 PWA
- 資料：Supabase（免費方案即可）；沒設定時自動進入 **Demo 模式**，資料存在瀏覽器
- 存取：要先註冊或登入（名稱＋數字密碼，不用 Email），只看得到自己是**成員**的旅程；旅程裡任何成員都能把其他註冊的人加進來或移出（見「[帳號與成員](#帳號與成員)」）
- 同時編輯：存檔後其他旅伴的畫面即時更新；兩個人同時改同一筆時會先問要不要覆蓋（見「[同時編輯](#同時編輯)」）
- 部署：GitHub Pages（GitHub Actions 自動部署），網址 `https://knowwhao.github.io/trip-planner/`
- 原始碼：<https://github.com/knowwHao/trip-planner>
- 姊妹專案：[球友記帳](https://github.com/knowwHao/sports-ledger)（架構與做法相同）

## 功能

- **登入**：打開網站時這台裝置沒登入就先顯示登入／註冊頁；註冊時輸入名稱會即時檢查，已經有人用的名稱會直接提示並擋下
- **我的旅程**（首頁）：自己是成員的旅程，進行中與還沒出發的依出發日排在前面、已結束的排在後面，標示「還有 N 天」「旅行中・第 N 天」「已結束」；「建立新旅程」填名稱、出發與回程日、當地幣別與匯率，勾選一起去的註冊使用者，另外可以填沒註冊、只用來記帳的旅伴
- **行程**：
  - 依天分段（第 1 天、第 2 天…），最後是「**口袋名單**」——想去但還沒排進行程的地方
  - 每個行程有類型（見「[類型與預約狀態](#類型與預約狀態)」）、名稱、時間、地址、Google 地圖連結、備註
  - **已過的天**：旅行中或已結束時，今天以前的天收合成「已過的 N 天」，點一下展開（顏色變淡、標示「已過」）；口袋名單不受影響。上方「新增行程」預設排進今天（還沒出發排第 1 天，已結束排最後一天），「還沒訂」也不算已過的天
  - **航班**：交通類型的編輯框有「✈️ 航班（選填）」：航空公司、航班號碼、出發與抵達機場、抵達時間（當地時間，可選隔天 +1、+2），起飛時間就是行程的「出發時間」；卡片上顯示「✈️ 日本航空 JL802 TPE 08:30 → NRT 12:45」，填了航班號碼還有「查航班動態」，開 [FlightAware](https://www.flightaware.com/) 的那班航班頁（不需要 API key）。航班號碼存成大寫英數，`jl 802` 會自動整理成 `JL802`；換成別的類型時航班資料會清掉
  - **行程的旅費**：有連結到這個行程的旅費時，卡片上顯示「$1,680・2 筆」，點開可以看明細、編輯或再記一筆；行程編輯框也有「記一筆旅費」。從行程記帳會帶入這個行程、那天的日期，品項先填行程名稱；記好的旅費一樣出現在「旅費」頁、一起結算
  - **子項目**：一個行程底下可以掛多個子項目，例如「銀座逛街」底下要逛的五間店；平常收合成「5 個店家・已逛 2」，點開後每間店可以打勾（已逛）、開 Google 地圖、拖曳排序、點名稱編輯；購物行程一定有「加入店家」入口，其他類型從編輯框的「新增地點」加。子項目存在獨立的 `spot_items` 表，兩個人同時勾不同店家不會衝突
  - 卡片右上角是預約狀態標籤（例如「未訂位」「已買票」），點一下就能在「還沒」與「已完成」之間切換，不用打開編輯框
  - 頂端篩選列：全部、「還沒訂 N」（還沒訂位、買票或預約的行程）、各類型；篩選時不能拖曳排序
  - 按住卡片左邊的把手可以拖曳排序，也能拖到別天或口袋名單；在編輯框改「哪一天」會排到那天最後面
  - 某天有時間的景點順序亂了，那天的標題旁會出現「依時間排」，按一下照時間重排（沒填時間的維持原本位置）
  - 每張卡片右邊的「地圖」直接開 Google 地圖：有貼連結就用連結，沒有就用地址搜尋（不需要 Google API key）；地址和連結都沒填就不顯示地圖（只用名稱搜尋常常搜到同名的別家店），子項目也一樣
  - 頂端日期列可以跳到某一天，今天會標出來
  - 旅程改短時，排在新天數之後的景點會先顯示在口袋名單（存檔前會提醒），之後可以再拖回去
- **旅費**：總花費與平均每人、轉帳建議（按「已轉帳」可改金額與日期後記下）、每個人的代墊／自己花／要收或要付、旅費紀錄（依日期分組，點一筆可編輯或刪除）、已轉帳紀錄（可刪除）
- **記一筆旅費**：品項 → 金額與幣別（當地幣別／新台幣切換）→ 實際扣款（外幣時選填，見「[實際扣款](#實際扣款)」）→ 誰付的 → 日期（列出旅程每一天，選填）→ 怎麼分（「勾選的人平分」或「各付各的金額」，見「[分攤](#分攤)」）→ 哪個行程（選填）、備註
- **設定**：旅程資訊（名稱、日期、當地幣別、匯率）、旅伴（加入成員、移出成員、把只記帳的旅伴換成帳號；只記帳的旅伴可以一次新增多位、改名、移除）、深色模式、退出這趟旅程、刪除整趟旅程
- 不是成員（被移出了）或旅程已被刪除時，開旅程網址會顯示「看不到這趟旅程」

## 類型與預約狀態

| 類型 | 預約狀態 |
|---|---|
| 🏯 景點 | 已買票／未買票／無需買票 |
| 🍜 餐廳 | 已訂位／未訂位／無需訂位 |
| 🛍️ 購物 | 沒有 |
| 🎟️ 活動體驗 | 已預約／未預約／無需預約 |
| 🚆 交通 | 已訂票／未訂票／無需訂票 |
| 🏨 住宿 | 已訂房／未訂房（住宿一定要訂，所以沒有「無需」） |
| 📍 其他 | 沒有 |

- 資料庫只存三種狀態：已完成（`done`）、還沒（`todo`）、不需要（`none`），畫面文字依類型換；加入類型功能前建立的行程一律是景點、狀態沒設定，卡片上顯示虛線的「設定預約」
- 新增有預約狀態的類型時預設「還沒」，比較不會漏訂；不用訂的要在編輯框改成「無需」
- 「無需」不顯示標籤，畫面比較乾淨；所以卡片上點標籤只在「還沒」與「已完成」之間切換，「無需」只能在編輯框設定
- 換類型時沿用原本的狀態，新類型不支援時改成預設值（例如住宿不能是「無需」）
- 「還沒訂」只算排進行程、還沒過的天；口袋名單裡的還沒決定要去，已過的天也來不及訂了，都不算
- 訂位時間、人數、訂位代號寫在備註
- 類型清單與文字在 `src/lib/category.ts`，要與 `schema.sql` 的 `spots.category` check 和 `spots_booking_fits_category` 一致

## 計算規則

### 幣別與匯率

- 每趟旅程設一個**當地幣別**與**匯率**（1 單位當地幣別 = 多少新台幣）；國內旅遊選新台幣，就不會出現換算
- 每筆旅費可以記當地幣別或新台幣（例如機票在台灣刷卡、餐廳付日圓）
- 金額的小數位數依幣別：新台幣、日圓、韓元等不能有小數，美元、歐元等最多兩位
- 結算一律用旅程**目前的**匯率換成新台幣，四捨五入到元；改了匯率，沒填實際扣款的外幣旅費都用新匯率重算
- 已經有當地幣別的旅費時不能換幣別（不然那些旅費會被當成新幣別算），要先改掉或刪掉那些旅費；這是在資料庫端強制的

### 實際扣款

刷卡或換匯的實際金額跟旅程匯率總有落差，外幣旅費可以另外填「實際扣款（新台幣）」，例如信用卡帳單上的金額：

- 有填就照實際扣款換算，這筆等於用「實際扣款 ÷ 外幣金額」當匯率，之後改旅程匯率也不受影響；畫面顯示「這筆用實際匯率 1 JPY ≈ 0.215 元換算」，旅費列表顯示「實扣 $2,150」
- 平分時：每人應付 = `ceil(實際扣款 ÷ 人數)`
- 各付各的金額時：依每人外幣金額的比例分配實際扣款，餘數給小數部分最大的人，加總**恰好等於**實際扣款，不會差 1 元
- 典型用法：一次結帳裡有幫別人買的東西——金額填這次結帳的外幣總額、實際扣款填帳單金額，選「各付各的金額」，朋友那欄填他那幾項（可以輸入 `1200+1800` 這樣的加法），再按「剩下的都算○○的」把剩下的算給付錢的人；沒參與的人留空就好
- 新台幣旅費本來就是實際金額，不能填實際扣款（資料庫端強制）

### 分攤

- **勾選的人平分**：先把金額換成新台幣，每人應付 = `ceil(新台幣金額 ÷ 人數)`（無條件進位），零頭由付錢的人多收，畫面標示「除不盡進位，付錢的人多收 $X」——與球友記帳相同
- **各付各的金額**：每個人填自己要付的金額（與這筆同幣別，可以輸入 `1200+1800` 這樣的加法），加總要剛好等於總額才能存檔；「剩下的都算○○的」把還沒分配的金額算給付錢的人，「剩下的平分給空白的人」把它平分給還沒填的人（除不盡的最小單位依序多分一點）；外幣且沒填實際扣款時，每個人的金額各自用旅程匯率換成新台幣後四捨五入，有填時見「[實際扣款](#實際扣款)」
- 付錢的人不一定要在分攤名單裡（例如幫別人付）

### 要付／要收（淨額）

```
淨額 = 代墊入帳 − 自己的應付總額 + 自己轉出的錢 − 自己收到的轉帳
```

- 正數＝別人要給他，畫面顯示「收 $X」；負數＝他要給別人，顯示「付 $X」；0 顯示「—」
- 「代墊入帳」以該筆旅費的**分攤加總**計（平分時含進位的零頭、指定金額時含四捨五入的差額），這樣全體淨額加總恰好為 0，轉帳建議才能把帳完全打平
- 「每個人」表格的「代墊」是付錢的人付出的新台幣金額（有實際扣款就是實際扣款）、「自己花」是自己的應付總額，兩者不含轉帳

### 轉帳建議（最少轉帳）

貪婪法：每次讓「欠最多的人」付給「應收最多的人」，金額取兩者較小值，直到全部歸零。轉帳後按「已轉帳」記下來，淨額與建議會跟著更新；轉帳一律記新台幣整數。

邏輯在 `src/lib/split.ts`，測試在 `src/lib/split.test.ts`。

## 同時編輯

- 有人存檔後，同一趟旅程的其他人畫面會自動更新；頁首旅程日期前的小圓點是綠色代表即時同步連線中
- 手機休眠或斷線時會漏掉通知，所以切回頁面、網路恢復、以及每 2 分鐘都會再讀一次
- 兩個人同時改同一筆（行程、子項目、旅費、旅程資訊、旅伴名字）：
  - 編輯框開著時別人先存了，框的上方會出現「別人剛改過這筆」，可以按「看最新」；被刪掉時會提示存檔會失敗
  - 存檔時版本對不上，會問「用我的覆蓋」還是「看最新版本」，不會默默蓋掉別人的修改
  - 拖曳排序只改天數與順序、子項目打勾只改「已逛」，都不算修改內容，不會讓別人正在編輯的那筆變成衝突
- 原理：
  - 行程、子項目、旅費、旅程、旅伴都有 `version`，內容欄位變動時由資料庫觸發器自動 +1；更新時帶上自己看到的版本號，對不上就更新 0 列，前端再分辨是別人改過、已被刪除還是已經不是成員
  - 存檔成功後經 Supabase Realtime 在這趟旅程的頻道廣播「有東西改了」，**不帶任何資料**，其他人收到後再以自己的登入身分經 RLS 重新讀取，所以知道頻道名稱也讀不到內容；頻道名稱是旅程 id 的 SHA-256
  - Demo 模式以瀏覽器的 BroadcastChannel 模擬，同一個瀏覽器開兩個分頁就能試

## 本機開發（Demo 模式）

需要 Node.js 22（22.12 以上）或 24，這是 vitest 5 的要求；CI 用 Node 22。

```bash
npm ci             # 依 package-lock.json 安裝
npm run dev        # http://localhost:5173
npm test           # 單元測試（vitest）
npm run build      # 型別檢查 + 打包到 dist/
```

不設定任何環境變數就會進入 Demo 模式：

- 頂端會出現「Demo 模式」提示條
- 一樣要先註冊；帳號只存在這個瀏覽器的 localStorage
- 首頁按「開一趟示範旅程」會建立一趟一個月後出發的東京五天四夜（你和 3 位只記帳的旅伴、各種類型與預約狀態的行程與口袋名單、有航班的去回程、銀座逛街底下的五間店、日圓與新台幣的旅費、平分與指定金額、一筆有實際扣款的代買、一筆已轉帳）；每按一次多一趟，不要的可以在設定刪除
- 想試加成員，就先登出、註冊第二個帳號，再登入回來加他
- 同一個瀏覽器開兩個分頁就能試同時編輯（同一個瀏覽器的分頁共用登入，換帳號時其他分頁也會跟著換）

## Supabase 設定

1. 到 [supabase.com](https://supabase.com) 建立新專案（Free 方案即可，每個帳號可同時有 2 個免費專案），記下資料庫密碼。本專案是東京區的 `trip-planner`。
2. 左側 **SQL Editor** → New query，把 [`supabase/schema.sql`](supabase/schema.sql) 整份貼上執行。這份 SQL 可以重複執行，之後改版也是貼整份再跑一次，會建立：
   - 資料表 `trips`、`participants`、`spots`（含類型 `category`、預約狀態 `booking`）、`spot_items`（子項目）、`expenses`（含實際扣款 `twd_amount`）、`expense_shares`、`transfers`，以及外鍵、索引；後來加的欄位以 `add column if not exists` 寫在一起，舊資料庫重跑整份就會升級；子表參照旅伴、景點、旅費一律用帶 `trip_id` 的複合外鍵，不可能把別趟旅程的資料掛進來
   - `accounts`：名稱、密碼的加鹽雜湊、登入憑證；前端完全讀不到，只能經 `account_register()`、`account_login()`、`account_name_available()`、`account_change_pin()`、`whoami()`、`list_accounts()` 存取
   - `participants.account_id`：有值就是成員，null 是只記帳的旅伴；同一趟旅程一個帳號只能出現一次
   - RLS：前端在每個請求帶 `x-account-id`、`x-account-key` header，`current_account_id()` 驗證登入憑證、`my_trip_ids()` 列出自己參加的旅程，每張表都只碰得到這些旅程；沒登入、憑證錯誤或不是成員時 select 是 0 筆、寫入被擋；`truncate` 權限已收回
   - `create_trip()`：登入的人才能呼叫，建立旅程、自己與勾選的成員、只記帳的旅伴；`trips` 不能直接新增
   - `add_trip_member()`／`remove_trip_member()`：成員才能呼叫；`account_id` 不能直接新增或修改。加入時有同名的只記帳旅伴就直接換成成員（旅費紀錄保留）；移出時留下名字變成只記帳的旅伴
   - `keep_one_member` 觸發器：旅程至少要留一位成員；`sync_member_name` 觸發器：成員的名字固定是帳號名稱
   - `save_expense()`：旅費連同分攤一起寫入，並檢查成員身分、幣別、指定金額加總與版本號
   - `bump_version()` 觸發器（內容變動時版本 +1）與 `check_trip_currency()` 觸發器（有外幣旅費時不能換幣別）
   - 從旅程連結版升級時，會刪掉 `trips.token`、`account_trips` 與舊的連結函式；舊旅程沒有成員，誰都看不到，要用下方「[把人加回旅程](#把人加回旅程)」的 SQL 補成員
   - 預設權限：之後在 `public` 新建的表、函式、序列不再自動授權給 `anon`／`authenticated`，要自己明確 grant
3. 這個專案**不使用 Supabase Auth**，但仍建議到 **Authentication → Sign In / Providers** 關閉 **Allow new users to sign up**：anon key 是公開的，不關閉的話任何人都能註冊成 `authenticated` 使用者（目前 RLS 對 `anon` 與 `authenticated` 一視同仁，註冊了也讀不到資料，關閉是多一層保險）。
4. Realtime 不用另外設定；如果曾經在 **Realtime → Settings** 關掉「Allow public access」，要打開，否則即時同步會失效（還是會在切回頁面時更新）。
5. 取得連線資訊：**Project Settings → API**（或 Data API），複製 **Project URL** 與 **anon public key**。
6. 本機要連 Supabase 的話，在專案根目錄建立 `.env.local`：

   ```bash
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

   `.env*` 已列在 `.gitignore`，不會被 commit。anon key 本來就會出現在前端，資料安全靠 RLS 保護；**絕對不要**把 `service_role` key 放進前端或 GitHub secrets。

Supabase 的安全檢查（Advisors）會對 `current_account_id()`、`my_trip_ids()`、`create_trip()`、`add_trip_member()`、`remove_trip_member()`、`whoami()`、`list_accounts()` 與 `account_*` 函式提出「anon 可以執行 SECURITY DEFINER 函式」的警告，這是刻意的：任何人都能註冊、登入與檢查名稱，其他函式都先驗證呼叫者帶的登入憑證，只作用在自己參加的旅程；`accounts` 表沒有 policy 也是刻意的（完全不授權）。

## 部署到 GitHub Pages

1. 在 GitHub 建立 repo（本專案是 `https://github.com/knowwHao/trip-planner`），把專案 push 到 `main`。
2. **Settings → Secrets and variables → Actions → New repository secret**，新增：
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

   （不設定也能部署，網站會以 Demo 模式運作。）
3. **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。
4. 之後每次 push 到 `main`，`.github/workflows/deploy.yml` 會跑測試、打包並部署。網址是 `https://<帳號>.github.io/<repo>/`，本專案為 `https://knowwhao.github.io/trip-planner/`；打包時會自動以 repo 名稱設定 Vite 的 `base`。第一次部署成功後，以 **Settings → Pages** 顯示的網址為準。
5. 路由使用 hash 模式（網址長得像 `.../#/trips/…`），GitHub Pages 重新整理深層頁面也不會 404。
6. 網站是 PWA，會用 service worker 快取整個網站。部署新版後，使用者下次打開網站（或把 App 從背景切回前景）時會在背景下載新版，畫面底部跳出「有新版本可以用了」，按「立即更新」就會重新載入成新版；按 ✕ 會先繼續用舊版，下次打開會再提示。正在填表單時不會自動重新整理，避免填到一半的內容消失。
7. 球友記帳也部署在同一個網域（`knowwhao.github.io`），兩個網站共用瀏覽器的 localStorage，所以本專案的鍵名一律以 `trip-` 開頭，避免互相覆蓋。

### 避免 Supabase 免費專案被暫停

Supabase 免費專案閒置一週會被暫停。`.github/workflows/keepalive.yml` 每天以 GET 呼叫一次 `/rest/v1/trips?select=id&limit=1`（沒帶登入憑證）保持活躍，預期回傳 200 與空陣列；回傳不是空陣列代表 RLS 失守，workflow 會失敗。secrets 沒設定時會直接成功跳過。

**注意**：
- 排程只會從預設分支（`main`）執行，workflow 檔要合併進 `main` 才會開始每天跑
- public repo 連續 60 天沒有任何活動（commit 等）時，GitHub 會自動停用 schedule 排程，keepalive 就不會再跑。停用期間只要 Supabase 連續 7 天沒有收到請求，專案就會被暫停。收到 GitHub 的停用通知或發現排程沒在跑時，到 repo 的 **Actions → Supabase keepalive** 頁面按 **Enable workflow** 重新啟用；專案若已被暫停，要到 Supabase Dashboard 手動恢復（Restore）

## 帳號與成員

- 打開網站要先登入；第一次用就「註冊」：自己取一個名稱（2～20 字，不分大小寫不能重複，輸入時會即時告訴你能不能用）、設 **6～8 位數字密碼**，不用 Email
- 這台裝置會記住登入，直到按「登出」（首頁右上角的名稱）或在別的裝置改密碼；在別的裝置用同一組名稱與密碼登入，就看得到同樣的旅程
- 旅伴有兩種：
  - **成員**：有註冊的人，看得到也能編輯這趟旅程；名字固定是帳號名稱
  - **只記帳**：沒註冊的人（例如長輩、小孩），只有名字，用來分旅費，看不到旅程；之後他註冊了，到 **設定 → 旅伴** 按名字旁的🔗選他的帳號，旅費紀錄會跟著保留
- 誰能看：只有成員；所有登入的人都看得到註冊使用者的名稱清單（加成員時要挑），但看不到別人的旅程
- 誰能加人、移人：旅程裡任何成員。**設定 → 旅伴 →「加入成員」**列出所有註冊的使用者；加入時旅程裡已有同名的只記帳旅伴，會直接把他換成成員
- 移出成員：他的旅費與轉帳紀錄留著，名字變成只記帳的旅伴，他立刻看不到這趟旅程；自己也能「退出這趟旅程」
- 旅程至少要留一位成員（資料庫端強制）；不需要這趟旅程時改用「刪除整趟旅程」，任何成員都能刪，會把行程、旅費、轉帳紀錄全部永久刪除，無法復原
- 做法與球友記帳的成員密碼相同：密碼只存加鹽雜湊，`accounts` 表前端讀不到；連續錯 5 次鎖 15 分鐘；改密碼後其他裝置要重新登入。密碼比球友記帳多兩位（6～8 位），因為帳號拿得到自己所有的旅程，4 位數在鎖定機制下幾天就試得出來

### 忘記密碼

網站上沒有重設功能（任何人都能按的話密碼就沒有意義），請到 Supabase Dashboard 的 **SQL Editor** 執行（把「小明」換成帳號名稱、`123456` 換成新的 6～8 位數字），重設密碼並讓他所有裝置登出：

```sql
update public.accounts a
   set pin_salt = s.salt,
       pin_hash = public.hash_account_pin(s.salt, '123456'),
       session_key = public.new_secret(),
       failed_attempts = 0,
       locked_until = null
  from (select public.new_secret() as salt) s
 where lower(btrim(a.name)) = lower('小明')
returning a.name;
```

被鎖定 15 分鐘但記得密碼的話，等時間到就能再試，不需要重設。

### 把人加回旅程

大家都被移出（例如從旅程連結版升級上來的舊旅程沒有成員）或需要直接補成員時，到 Supabase Dashboard 的 **SQL Editor** 執行（把「東京五天四夜」換成旅程名稱、「小明」換成帳號名稱）；已經有同名的只記帳旅伴時會直接把他換成成員：

```sql
insert into public.participants (trip_id, name, account_id)
select t.id, a.name, a.id
  from public.trips t, public.accounts a
 where t.name = '東京五天四夜' and lower(btrim(a.name)) = lower('小明')
on conflict (trip_id, name) do update set account_id = excluded.account_id
returning name;
```

SQL Editor 以資料表擁有者 `postgres` 身分執行，不受 RLS 限制。
